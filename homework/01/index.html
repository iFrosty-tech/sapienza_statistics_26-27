§1 Problem statement

The assignment reads, verbatim:

HMWK 1 — Example App: Public-Key Cryptography PRIVATE KEY → PUBLIC KEY in Ethereum

Notes: Elliptic-curve scalar multiplication can be viewed as a cryptographic one-way function. It is deterministic and easy to compute in the forward direction: private key k → public key Q = kG while recovering k from Q is computationally difficult. It therefore shares some properties with cryptographic hash functions, but it is based on the Elliptic Curve Discrete Logarithm Problem (ECDLP) and is used for public-key cryptography and digital signatures.

The goal is to understand the basic idea of elliptic-curve scalar multiplication, not to implement a real cryptographic system.

TASK

Write a small JavaScript/html/css program showing how a private key can be used to generate a public key using elliptic-curve scalar multiplication. (In Ethereum, the relevant elliptic curve is secp256k1).

Hints: For this exercise, use a small toy curve: y² = x³ + 7 (mod 17)

For example, use for instance the following base point: G = (1, 5) Choose for instance a small private key: k = 6

The public key is: Q = kG Define the toy curve and the base point G. Define the private key k.

Implement the basic point-addition operation. Compute and print: G, 2G, 3G, ..., kG. Or use afaster method for a larger k.

Print the final point as the TOY PUBLIC KEY.

OPTIONAL-GURU LEVEL :-) Make a slown-down visual representation of the algo (may use the canvas or SVG, whatever you like better)

== STATISTICAL EXPLORATION ==

Repeat the experiment with different values of k and, if useful, different valid base points.

Explore simple statistical properties of the resulting points, for example:

  • distribution of x and y coordinates;
  • frequency of individual values;
  • distribution of bits;
  • apparent uniformity;
  • correlations between input and output;
  • possible avalanche-like behaviour.

Discuss which of these properties are meaningful for a cryptographic one-way function and which are properties specifically associated with cryptographic hash functions.

The assignment has three practical parts and a question. The program of §3 computes the toy public key Q = 6G = {{fig.toy.Q}} by repeated point addition, printing G, 2G, \dots, 6G, and by the faster double-and-add method; it is also provided as a standalone file. The slowed-down view of §4 answers the optional "guru level" by replaying each group operation on the lattice of the toy curve. The statistical exploration of §5 repeats the experiment over many keys and base points, and §6 answers the question by classifying each property explored as meaningful for a one-way function, specific to hash functions, or both; §7 concludes.

"One-way" is meant in its computational sense: a function is one-way when it is easy to compute and hard to invert, in that no efficient algorithm given f(x), for a uniformly random input x, finds a preimage with more than negligible probability [7, §8.1.1]; it is the notion on which Diffie and Hellman founded public-key cryptography [5, §IV]. The toy curve cannot have this property. Its private keys fit on one line and the logarithm of any of its points can be read off a table: it teaches the mechanism, not the security. For this reason §5 runs the same experiments on a ladder of curves of growing size, up to secp256k1 itself, so as to separate the artefacts of smallness from the properties of the map k \mapsto kG. The research question is therefore twofold: which statistical properties of Q = kG can a sample of keys reveal, and which of them matter for the one-wayness on which an Ethereum key rests?

§2 Background

2.1 Elliptic curves over a prime field

Let p > 3 be a prime and \mathbb{F}_p the field of the integers modulo p. An elliptic curve over \mathbb{F}_p is the set of solutions (x, y) \in \mathbb{F}_p^2 of an equation y^2 = x^3 + ax + b with 4a^3 + 27b^2 \not\equiv 0 \pmod p, together with an extra point O, the point at infinity [3, §2.2.1]. The condition excludes singular curves. For the curves of this page, a = 0 and b = 7, it reads 27 \cdot 49 = 3^3 \cdot 7^2 \not\equiv 0, which holds for every prime p > 3 except p = 7.

The points form an abelian group under the chord-and-tangent rule, with O as identity (Figure 1, over the real numbers). To add P = (x_1, y_1) and Q = (x_2, y_2), draw the line through them, or the tangent when P = Q; it meets the curve in a third point R', and P + Q is the reflection of R' in the horizontal axis. The negative of (x, y) is (x, -y): the line through a point and its negative is vertical, meets the curve nowhere else, and their sum is O. Over \mathbb{F}_p the geometry gives way to algebra, with the same formulas [3, §2.2.1]: the slope of the line is

\lambda = \frac{y_2 - y_1}{x_2 - x_1} \quad (P \ne Q), \qquad \lambda = \frac{3x_1^2 + a}{2y_1} \quad (P = Q),
(1)

and the sum P + Q = (x_3, y_3) has the coordinates

x_3 = \lambda^2 - x_1 - x_2, \qquad y_3 = \lambda(x_1 - x_3) - y_1 .
(2)

All the arithmetic is modular. A division is a multiplication by the inverse of the denominator modulo p, which exists because p is prime and is computed by the extended Euclidean algorithm; the reflection -y is the residue p - y. The number of points cannot stray far from p + 1: by Hasse's theorem, |\#E(\mathbb{F}_p) - (p + 1)| \le 2\sqrt{p} [13, Thm 4.2]. Elliptic curves were proposed for cryptography independently by Miller [9] and Koblitz [8], as groups in which to run cryptosystems based on the discrete logarithm.

2.2 Scalar multiplication and the discrete logarithm

For a positive integer k, scalar multiplication repeats the group law, kG = G + G + \cdots + G with k terms, and 0G = O. If n, the order of G, is the smallest positive integer with nG = O, the multiples of G form a cyclic subgroup \langle G \rangle of n points, and k \mapsto kG is a group homomorphism from \mathbb{Z}/n\mathbb{Z} onto \langle G \rangle: (a + b)G = aG + bG, and kG depends only on k modulo n. Restricted to \{0, 1, \dots, n - 1\} it is a bijection, so every point of \langle G \rangle has exactly one discrete logarithm in that range.

Computed from its definition, kG costs k - 1 additions, which is out of reach for the 256-bit keys of practice. The left-to-right binary method, or double-and-add, reads the bits of k from the most significant one, doubles an accumulator at every bit and adds G at every bit equal to one [6, Alg. 3.27]; it needs at most 2\log_2 k group operations (§3.3).

The inverse problem, to find k from G and Q = kG, is the elliptic-curve discrete logarithm problem (ECDLP). Exhaustive search tries k = 1, 2, \dots and needs about n/2 additions on average. Generic algorithms, which use nothing but the group operations, do better, though not by much: baby-step giant-step needs of the order of \sqrt{n} operations and as many stored points [13, §5.2.1], and Pollard's rho method an expected \sqrt{\pi n/2} steps with negligible memory [6, §4.1.2]. When n is composite, the Pohlig–Hellman method reduces the problem to subgroups of prime order, so that its cost is governed by the largest prime factor of n [6, §4.1.1], [13, §5.2.3]; this is why cryptographic base points have prime order. Supersingular curves are weaker still, because the MOV attack transfers the problem to a discrete logarithm in the multiplicative group of a small extension of \mathbb{F}_p [13, §5.3.1].

The asymmetry between a forward cost that grows with \log n and an inverse cost that grows with \sqrt{n} for the best generic algorithms is what makes k \mapsto kG a candidate one-way function: a function that is easy to compute but hard to invert on uniformly random inputs [7, §8.1.1]. Diffie and Hellman framed public-key cryptography in terms of such functions and of trap-door one-way functions, which become easy to invert with a secret [5, §IV–V]. For scalar multiplication the hardness of inversion is an assumption, not a theorem: it rests on the absence of known algorithms substantially faster than the generic ones on curves of prime order that avoid the special cases above.

2.3 From a private key to an Ethereum address

Ethereum uses the curve secp256k1 of the SEC 2 standard: the equation y^2 = x^3 + 7, so a = 0 and b = 7, over \mathbb{F}_p with p = 2^{256} - 2^{32} - 977, and a base point G of prime order n, slightly below 2^{256}, with cofactor 1, so that G generates the whole group [4, §2.4.1]. It is the toy curve's equation with a different prime; its parameters are printed in the appendix. Key pairs are generated as in SEC 1: an integer d (k on this page) is selected randomly or pseudorandomly in [1, n - 1] and the public key is Q = dG [3, §3.2.1], and the standard asks that private keys have a distribution as close as possible to uniform [3, §3.10.3].

The Ethereum yellow paper adopts this scheme. A private key is an integer in [1, \mathtt{secp256k1n} - 1]; the public key is the 64-byte concatenation x \,\|\, y of the coordinates of Q, without the 04 prefix of the uncompressed encoding of SEC 1 [3, §2.3.3]; and the address is the rightmost 160 bits of the Keccak-256 hash of those 64 bytes [15, App. F, eqs (309) and (316)]. Keccak-256 is the function KEC of the yellow paper, the Keccak submitted to the SHA-3 competition rather than the final SHA-3 standard [15, §3]. The two are not interchangeable: SHA3-256 appends the domain-separation suffix 01 to the message before padding [10, §6.1], whereas the Keccak-256 used by Ethereum, defined before standardisation, does not.

The path from a private key to an address therefore passes through two one-way maps in series, of different kinds. The first, k \mapsto kG, is algebraic: it is a homomorphism, and it is hard to invert only because the ECDLP is hard. The second, Keccak-256, is a hash: it compresses its input and is designed so that no exploitable algebraic relation between its inputs and outputs is known. Homework 2 follows the whole wallet pipeline, from a mnemonic sentence to the address; this page studies the first map, with the second as the baseline against which its statistics are compared.

One difference between the toy curve and secp256k1 matters later. For p \ge 5, a curve over \mathbb{F}_p is supersingular exactly when it has p + 1 points [13, Cor. 4.32], and a curve y^2 = x^3 + b is supersingular whenever p \equiv 2 \pmod 3 [13, Prop. 4.33]. The toy prime is 17 \equiv 2 \pmod 3, so the toy curve is supersingular, with p + 1 = 18 points. For secp256k1, p \equiv 1 \pmod 3 and the number of points is the odd prime n, which cannot equal the even number p + 1: the curve is ordinary [13, Cor. 4.32].

§3 The toy program

3.1 The curve y² = x³ + 7 (mod 17)

Over \mathbb{F}_{17} the equation y^2 = x^3 + 7 has {{fig.toy.points}} solutions (Figure 2), and with O the group has {{fig.toy.order}} elements: exactly p + 1, as for every supersingular curve, and well inside the Hasse interval. Each row of the lattice in Figure 2 holds exactly one point. Since \gcd(3, 16) = 1 and 16 is the order of the multiplicative group of \mathbb{F}_{17}, cubing is a bijection of the field; so for every ordinate y the equation x^3 = y^2 - 7 has exactly one solution, and each of the 17 values of y occurs once. The abscissas are less even. As x runs over the field, x^3 + 7 also takes every value once, and only 9 of these values, the 8 non-zero squares and zero, are of the form y^2: 9 abscissas occur, 8 of them twice, as (x, y) and (x, 17 - y), and x = 3 once, as the point (3, 0). The mirror (x, y) \leftrightarrow (x, 17 - y) about the dashed line y = 17/2 is the map P \mapsto -P.

Table 1 groups the points by order. The group is cyclic of order 18, so for every divisor d of 18 it has exactly \varphi(d) elements of order d, where \varphi is Euler's function: six generators of order 18, among them {{fig.toy.generator}}; six points of order 9; two of order 6; two of order 3; and (3, 0), of order 2. The base point of the assignment, G = {{fig.toy.G}}, has order {{fig.toy.orderG}}. It does not generate the whole group but its subgroup of index 2, the nine points G, 2G, \dots, 8G, O; the statistical exploration of §5 therefore also uses the generator {{fig.toy.generator}}, whose multiples visit all 17 affine points.

3.2 Computing Q = 6G step by step

Table 2 computes 2G, 3G, \dots, 6G by five successive group operations, each an application of formulas (1) and (2) with all arithmetic modulo 17. The first is a doubling, since 2G = G + G, and its slope is \lambda = (3 \cdot 1^2 + 0)/(2 \cdot 5) = 3/10. Dividing by 10 means multiplying by its inverse, 10^{-1} \equiv 12 \pmod{17} because 10 \cdot 12 = 120 = 7 \cdot 17 + 1; hence \lambda \equiv 3 \cdot 12 = 36, which reduces to {{fig.toy.slope.2}}. Then x_3 = 2^2 - 1 - 1 = 2 and y_3 = 2(1 - 2) - 5 = -7 \equiv 10, so that 2G = {{fig.toy.multiple.2}}. The other four rows add G to the previous multiple in the same way. The program prints the same sequence (Listing 1) and ends with the toy public key Q = 6G = {{fig.toy.Q}}.

Since 9G = O, only the residue of k modulo 9 matters: k and k + 9 give the same point, and k = 9 gives O, which has no coordinates and cannot serve as a public key; the program says so if asked for it. The usable keys for G = (1, 5) are therefore k \in \{1, \dots, 8\}, the toy counterpart of the interval [1, n - 1] of SEC 1 [3, §3.2.1].

3.3 A faster method: double-and-add

The assignment's key is k = 6, or {{fig.toy.bits}} in binary. Double-and-add reads these bits from the most significant one (Table 3): the leading 1 loads G; the second bit doubles the accumulator to 2G and, being 1, adds G to give 3G; the last bit, 0, doubles 3G to 6G. The method reaches {{fig.toy.Q}} in {{fig.toy.dblAddOperations}} group operations, {{fig.toy.dblAddDoublings}} doublings and {{fig.toy.dblAddAdditions}} addition, instead of the {{fig.toy.repeatedOperations}} additions of the repeated method.

In general, a key of L = \lfloor \log_2 k \rfloor + 1 bits, w of them equal to one, costs L - 1 doublings and w - 1 additions. For a 256-bit key with uniformly random lower bits this is 255 doublings and on average 127.5 additions, {{fig.dblAddCost.meanDoubleAndAdd256}} group operations in all, whereas repeated addition would need on average about 2{{fig.dblAddCost.log2Repeated256}} (Figure 3). The gap is the quantitative content of the word "one-way": the forward direction costs a number of operations proportional to \log_2 n, while the best known generic inversion costs about \sqrt{n}, which for n \approx 2^{256} is about 2^{128} (§5.8).

3.4 The program

The standalone program is a single HTML file, with its style sheet and script inline, and follows the steps of the assignment in order. It defines the curve (p = 17, a = 0, b = 7), the base point G = (1, 5) and the private key k = 6 as constants. It computes inverses modulo p by the extended Euclidean algorithm and implements point addition by formulas (1) and (2), with the special cases of the identity O, of a point and its negative, whose sum is O, and of doubling. It multiplies by both methods: repeated addition, which keeps every multiple, and double-and-add, which keeps a record of each operation. Its report prints G, 2G, \dots, kG, or the record of double-and-add, and ends with the line TOY PUBLIC KEY. A small form lets the reader choose another key, any of the 17 points as base point, and the method; repeated addition is limited to k \le 10\,000.

Automated tests run the program's own code and check that its report for the assignment is exactly Listing 1, and that it agrees with the arithmetic library that produces Tables 1 to 3 for every one of the 17 base points and every k from 1 to 40, by both methods. The live version of the program in Listing 1 uses that library and adds the real curve: on secp256k1 it computes Q = kG for any key in [1, n - 1], prints its coordinates and derives the Ethereum address of §2.3. The private key 1, whose public key is G itself, gives the address 0x7E5F4552091A69125d5DfCb7b8C2659029395Bdf, a value the test suite also checks.

§4 A slowed-down view of the algorithm

Figure 4 replays the computation of Q = kG one group operation at a time, at a pace the eye can follow, and in the order of formulas (1) and (2). The two operands pulse. The line through them, or the tangent for a doubling, is the set of solutions of y \equiv \lambda x + \nu \pmod{17}; on the flat sheet it appears as parallel segments of slope \lambda that leave the sheet at one edge and re-enter at the opposite one, passing through exactly 17 lattice points, one in each column, unless the line is vertical. Its third intersection with the curve, R' = (x_3, y'), appears as an open ring. A dashed drop then reflects R' across the line y = 17/2, because the negative of a point has the ordinate -y' \equiv 17 - y', and the red accumulator lands on the result. Beside the sheet, the arithmetic panel writes the same steps in numbers: the slope \lambda with its modular inverse spelled out, the intercept \nu, the abscissa x_3, the ordinate y' of R' and the ordinate y_3 of the result.

The torus view makes the wrapping literal. Gluing the top edge of the sheet to the bottom one and the left edge to the right one turns the square into a torus, on which the parallel segments of a line modulo 17 join into a single closed curve, and the reflection y \mapsto 17 - y becomes the mirror symmetry through the plane of the two equators.

The dial beside the sheet shows the same computation in the group. Its n ticks are the multiples of G in the order of their index, and its hand marks the index of the accumulator modulo n: one tick forward for each addition of G, a jump from i to 2i for each doubling. Repeated addition is therefore a regular rotation, one tick per step. On the sheet the same steps jump between distant points with no visible order: for the assignment the accumulator visits {{fig.toy.multiple.1}}, {{fig.toy.multiple.2}}, {{fig.toy.multiple.3}}, {{fig.toy.multiple.4}}, {{fig.toy.multiple.5}} and {{fig.toy.multiple.6}}. This contrast is the one-way property in miniature. A public key tells where the accumulator stopped on the sheet; the private key is where the hand stopped on the dial; recovering the second from the first is the ECDLP. For the assignment the dial has {{fig.toy.orderG}} ticks and can be read by inspection, or by replaying the rotation until the accumulator reaches Q. On secp256k1 the dial has about 2^{256} ticks, and no known generic method locates the hand in substantially fewer than about \sqrt{n} steps (§5.8).

§5 Statistical exploration

5.1 Experimental design

A statistical property observed on the toy curve could belong to scalar multiplication or be an artefact of having only 17 points, on which almost any pattern, or none, can arise by chance. The experiments are therefore repeated on the ladder of curves y^2 = x^3 + 7 of Table 4: the toy curve, with the assignment's base point and with a generator; a supersingular curve with p = 1031 \equiv 2 \pmod 3, like the toy; two curves of prime order with p = 1051 and p = 16477, both \equiv 1 \pmod 3 like secp256k1; and secp256k1 itself. A property that persists from \mathbb{F}_{17} to secp256k1 belongs to the map; one that fades as p grows belongs to smallness; one that follows the residue of p modulo 3 belongs to the arithmetic of the field.

The small and medium curves are enumerated: every key from 1 to n - 1 is used once. Since k \mapsto kG is a bijection from \{1, \dots, n - 1\} onto \langle G \rangle \setminus \{O\}, the enumeration is the exact distribution of the public key under a uniformly random private key, and its statistics are population values, not estimates. A chi-square p-value computed on them does not test a hypothesis about a population that has been observed in full; it answers a counterfactual question, whether n - 1 independent uniform draws would often differ from the reference as much as these points do, and it is quoted as a yardstick only. On secp256k1 enumeration is impossible: the {{fig.params.sampleN}} private keys are a sample, drawn uniformly from [1, n - 1] with the seed {{fig.params.seed}} (appendix), and there the tests are genuine inference about the population of all public keys.

Keccak-256 is applied to the same keys, written as 32 bytes, as the baseline of a hash function, so that both maps receive exactly the same inputs. The null models are those of an ideal function. For the coordinates it is the uniform law on the integers of [0, p). For the frequencies of values, the bits and the avalanche it is a random function, which gives every input an independent, uniformly distributed output: the random oracle through which Bellare and Rogaway idealise a hash function in the design of protocols [1, §1.1]. Where the size of the field or the structure of an orbit makes these references inexact, the text replaces them with exact or simulated ones (§5.2, §5.4 and §5.7).

5.2 Distribution of the coordinates

If the public key were a uniformly random point of the plane, its abscissa and its ordinate would each be uniform on the integers of [0, p). Figure 5 sorts x/p and y/p into B equal bins and compares the counts with their exact expectation under that law by a chi-square statistic. For a sample the statistic is referred to \chi^2(B - 1) and the test is genuine: the sample of secp256k1 passes it, with {{fig.coordHist.secp256k1.xPEq}} for x and {{fig.coordHist.secp256k1.yPEq}} for y, and so do the Keccak-256 digests of the same keys ({{fig.coordHist.keccak.xPEq}}). For an enumeration the \chi^2(B - 1) p-value is a yardstick only (§5.1), and for these coordinates an inexact one, for the reasons given below. The figure therefore also refers each statistic to a structural Monte Carlo null: {{fig.params.structuralReplicates}} random configurations that keep the multiplicity of every value and, for the ordinates, the mirror pairs \{y, p - y\}, and change only where the values lie. At this resolution the abscissas of \mathbb{F}_{1051} look uniform against either reference, with \chi^2 = {{fig.coordHist.O1051.xStatistic}} on {{fig.coordHist.O1051.xDf}} degrees of freedom (yardstick {{fig.coordHist.O1051.xPEq}}; structural null {{fig.coordHist.O1051.xStructuralPEq}}), and both coordinates of \mathbb{F}_{16477} are compatible with the structural null ({{fig.coordHist.O16477.xStructuralPEq}} for x and {{fig.coordHist.O16477.yStructuralPEq}} for y).

The ordinates of \mathbb{F}_{1051} are the exception. Their statistic, \chi^2 = {{fig.coordHist.O1051.yStatistic}}, lies far in the tail of \chi^2({{fig.coordHist.O1051.yDf}}) ({{fig.coordHist.O1051.yPEq}} as a yardstick), yet they show no preference for particular values. What \chi^2(B - 1) ignores is their multiplicity: when p \equiv 1 \pmod 3 every ordinate that occurs belongs to exactly three points (§5.3). For a coordinate whose D distinct values are each shared by m points, the variance of a bin count is about m(1 - d) times that of independent draws, with d = D/p the fraction of the field that occurs, whereas \chi^2(B - 1) assumes the factor 1. For the ordinates of \mathbb{F}_{1051}, shared by three points and taking D = {{fig.coordHist.O1051.yDistinct}} values, the factor is {{fig.coordHist.O1051.yVif}}; for the abscissas, which come in pairs (D = {{fig.coordHist.O1051.xDistinct}}), it is {{fig.coordHist.O1051.xVif}}, close to 1. Moreover the set of ordinates of a subgroup is closed under y \mapsto p - y, so bins j and B - 1 - j hold identical counts, which leaves the mean of the statistic unchanged but about doubles its variance. A null that keeps both structures is the honest yardstick, and \chi^2(B - 1) is not. Under it the statistic of the ordinates has mean {{fig.coordHist.O1051.yStructuralMean}} and 95th percentile {{fig.coordHist.O1051.yStructuralQ95}}, and the observed {{fig.coordHist.O1051.yStatistic}} lies in its upper tail ({{fig.coordHist.O1051.yStructuralPEq}}): a mild departure, not the decisive rejection that \chi^2({{fig.coordHist.O1051.yDf}}) suggests. The ordinates of \mathbb{F}_{16477} share both structures (factor {{fig.coordHist.O16477.yVif}}) and give \chi^2 = {{fig.coordHist.O16477.yStatistic}}, below the structural mean of {{fig.coordHist.O16477.yStructuralMean}}.

Behind the bins, the support is structured on every curve. Only about half the abscissas occur, {{fig.occupancy.O1051.xHits2}} of the {{fig.ladder.O1051.p}} values of \mathbb{F}_{1051}, because x^3 + 7 must be a square. When p \equiv 2 \pmod 3, on the other hand, the ordinates are exactly uniform, each value of the field occurring once (§3.1): their statistic is {{fig.coordHist.S1031.yStatistic}} on \mathbb{F}_{1031} ({{fig.coordHist.S1031.yPEq}} as a yardstick) and {{fig.coordHist.T17g.yStatistic}} on the toy curve with the generator. The statistic of a random sample would scatter around its {{fig.coordHist.S1031.yDf}} degrees of freedom; a fit this good is itself a sign of structure.

5.3 Frequency of individual values

A random function that sends n - 1 inputs into the p values of \mathbb{F}_p hits each value a number of times that follows, approximately, the Poisson law of mean \theta = (n - 1)/p: for \theta near 1, values hit once are about as common as values never hit, and a few are hit three times or more. Figure 6 counts how many values of the field occur m times as a coordinate of kG, and the curves look nothing like a random function. On \mathbb{F}_{1051} the abscissas take {{fig.occupancy.O1051.xPattern}}, and the ordinates {{fig.occupancy.O1051.yPattern}}. Against the Poisson law, whose mean \theta is set to the observed mean and so costs one degree of freedom, the chi-square statistics are {{fig.occupancy.O1051.xStatistic}} for the abscissas and {{fig.occupancy.O1051.yStatistic}} for the ordinates, on {{fig.occupancy.O1051.xDf}} and {{fig.occupancy.O1051.yDf}} degrees of freedom ({{fig.occupancy.O1051.xPEq}} and {{fig.occupancy.O1051.yPEq}}, as yardsticks). Keccak-256 reduced modulo the same p and applied to the same keys follows the Poisson law, with {{fig.occupancy.keccakO1051.xPattern}} (\chi^2 = {{fig.occupancy.keccakO1051.xStatistic}} on {{fig.occupancy.keccakO1051.xDf}} degrees of freedom, yardstick {{fig.occupancy.keccakO1051.xPEq}}).

Both patterns are exact consequences of the equation. An abscissa is shared by the points (x, y) and (x, p - y), that is by Q and -Q, the images of k and n - k; so every abscissa occurs twice or never, except that of a point with y = 0, which has order 2, belongs to the orbit when the order of G is even (on \mathbb{F}_{1031} and on the toy curve with the generator) and occurs once. When p \equiv 1 \pmod 3 the field contains a cube root of unity \beta \ne 1, the equation x^3 = y^2 - 7 has three solutions or none, and the points (x, y), (\beta x, y) and (\beta^2 x, y) share their ordinate, which therefore occurs three times or never; a point with x = 0 would be the exception, and neither of these two curves has one. When p \equiv 2 \pmod 3 cubing is a bijection and every ordinate occurs exactly once (§3.1), the pattern of \mathbb{F}_{1031} and of the toy curve with the generator.

The frequency test thus detects structure at once, and with certainty. The structure is the known symmetry of the group, however, not a leak of the key. Q and -Q come from k and n - k; and since (x, y) \mapsto (\beta x, y) is an automorphism of a cyclic group of prime order, it multiplies every key by one fixed \mu, so that the three points sharing an ordinate come from k, \mu k and \mu^2 k modulo n. Knowing this shortens a search by a small constant factor, nothing more. The same patterns hold exactly on secp256k1, whose prime is also \equiv 1 \pmod 3, but a sample of {{fig.params.sampleN}} keys out of about 2^{256} contains, with overwhelming probability, no two points with a coordinate in common, so the test cannot even be computed there (Table 7).

5.4 Distribution of bits

Figure 7 counts the ones at each bit position j of the abscissa. The natural reference, one half, is wrong for a coordinate. A uniform integer on [0, p) has bit j equal to one with an exact probability q_j, which differs from one half in the top bits whenever p is not a power of two. On \mathbb{F}_{1051} the top bit is set only for the 27 integers from 1024 to 1050, so that q_{10} = {{fig.bitFreq.O1051.topExpected}}, and the multiples of G give {{fig.bitFreq.O1051.topObserved}}. Against one half the largest standardised deviation over the bit positions is |z| = {{fig.bitFreq.O1051.maxAbsZHalf}}; against q_j it is {{fig.bitFreq.O1051.maxAbsZExact}}. On \mathbb{F}_{17} the top bit of x is never one, because the only value below 17 that sets it, 16, is not an abscissa.

secp256k1 is the opposite extreme. Its prime falls short of 2^{256} by only c = 2^{32} + 977, so the top bit of a uniform integer on [0, p) is one with probability \tfrac12 - c/(2p) \approx \tfrac12 - 2^{-225}, and no bit departs from one half by more: removing the c integers of [p, 2^{256}) from [0, 2^{256}), where every bit is exactly balanced, changes each count of ones by at most c. The sample agrees. The sum of the squared standardised counts over the 256 positions is {{fig.bitFreq.secp256k1.statistic}} on {{fig.bitFreq.secp256k1.df}} degrees of freedom ({{fig.bitFreq.secp256k1.pEq}}), and the frequency (monobit) test of NIST SP 800-22, applied to all the bits of the sample as one sequence [12, §2.1], gives {{fig.bitFreq.secp256k1.monobitPEq}}; for the Keccak-256 digests the same tests give {{fig.bitFreq.keccak.pEq}} and {{fig.bitFreq.keccak.monobitPEq}}. A bias in the bits of a coordinate is thus a property of the size of the field, shared by every point whatever its key, and not a property of the map from keys to points.

5.5 Apparent uniformity

Drawn as clouds of points (Figure 8), the multiples kG look like noise: no line, cluster or gap stands out. Yet the mirror image (x, p - y) of every point is present, {{fig.pointCloud.O1051.mirrored}} of {{fig.pointCloud.O1051.total}} on \mathbb{F}_{1051} and {{fig.pointCloud.O16477.mirrored}} of {{fig.pointCloud.O16477.total}} on \mathbb{F}_{16477}: an exact symmetry, which a uniform scatter of the same size would show with vanishing probability. The symmetry also shapes the cell test. Over the whole plane every cell would have a mirror cell holding exactly the same count, which would double the variance of the statistic; the test therefore divides only the lower half y < p/2 into equal cells and compares their counts with the uniform law on the half lattice. There the clouds look uniform: \chi^2 = {{fig.pointCloud.O1051.cellsStatistic}} for the {{fig.pointCloud.O1051.cellsPoints}} points of the lower half of \mathbb{F}_{1051} on {{fig.pointCloud.O1051.cells}} cells ({{fig.pointCloud.O1051.cellsDf}} degrees of freedom, yardstick {{fig.pointCloud.O1051.cellsPEq}}), and {{fig.pointCloud.O16477.cellsStatistic}} for the {{fig.pointCloud.O16477.cellsPoints}} points of the lower half of \mathbb{F}_{16477} on {{fig.pointCloud.O16477.cells}} cells ({{fig.pointCloud.O16477.cellsDf}} degrees of freedom, yardstick {{fig.pointCloud.O16477.cellsPEq}}). On the toy curve the {{fig.pointCloud.T17g.cellsPoints}} points of the lower half fall into {{fig.pointCloud.T17g.cells}} cells whose expected counts are as low as {{fig.pointCloud.T17g.cellsMinExpected}}, below the usual minimum of 5, so its statistic, {{fig.pointCloud.T17g.cellsStatistic}}, is illustrative only and supports no inference. "Looks uniform" is a statement about one test at one resolution; "is random" is a statement about every test, and the clouds pass the first while failing the second by construction.

5.6 Correlation between input and output

Table 5 asks whether the output carries a linear or monotone trace of the input. Over every full orbit, Pearson's r between k and x(kG) is exactly zero, and so is Spearman's \rho. The reason is not independence. Since (n - k)G = -kG, the keys k and n - k, placed symmetrically about their mean n/2, have the same abscissa, and their contributions to the covariance cancel in pairs. Yet the abscissa is a deterministic function of the key, the strongest dependence there is. Zero correlation and independence are different things, and the orbit shows it without any sampling error.

The other coefficients are small on the larger curves: r(k, y) = {{fig.correlation.O1051.kyR}} on \mathbb{F}_{1051} and {{fig.correlation.O16477.kyR}} on \mathbb{F}_{16477}, and the lag-one correlation of consecutive abscissas {{fig.correlation.O1051.lag1R}} and {{fig.correlation.O16477.lag1R}}. On the eight points of the toy orbit they are larger, {{fig.correlation.T17.kyR}} and {{fig.correlation.T17.lag1R}}, which says more about eight points than about the map. A test aimed at the right structure finds it with certainty: the correlation of the mirror pairs x(kG), x((n - k)G) is {{fig.correlation.O1051.mirrorR}} on every enumerated curve, and on the toy curve the sequence x(kG) repeats with period {{fig.sequence.T17.period}}, the order of G (Figure 9). On secp256k1 the sample gives r(k/n, x/p) = {{fig.correlation.secp256k1.kxR}} ({{fig.correlation.secp256k1.kxPEq}}), indistinguishable from zero, as is the coefficient for Keccak-256, {{fig.correlation.keccak.kxR}} ({{fig.correlation.keccak.kxPEq}}). Correlation tests are a necessary screen, since a strong correlation would betray the key, but a weak one: they see only the relations they are built to see.

5.7 Avalanche-like behaviour

The avalanche experiments ask how much the output changes when one bit of the input changes. On secp256k1, flipping one random bit i of each key, k' = k \oplus 2^i, changes on average {{fig.avalanche.secp256k1.mean}} of the 256 bits of x(Q), against {{fig.avalanche.secp256k1.expectedMean}} for independent fair bits, and the distribution of the Hamming distance is consistent with \mathrm{Bin}(256, \tfrac12) ({{fig.avalanche.secp256k1.pEq}}); Keccak-256 behaves in the same way on the same flips, with mean {{fig.avalanche.keccak.mean}} ({{fig.avalanche.keccak.pEq}}) (Figure 10). The strict avalanche criterion of Webster and Tavares asks more: that each output bit change with probability one half whenever a single input bit is complemented [14]. Figure 11 estimates all 256 \times 256 of these probabilities from {{fig.sac.secp256k1.trials}} keys, and both functions meet the criterion within sampling error. The largest deviation from one half is {{fig.sac.secp256k1.maxAbsDeviation}} for scalar multiplication and {{fig.sac.keccak.maxAbsDeviation}} for Keccak-256, and the cells with |z| > 3.29 number {{fig.sac.secp256k1.beyond}} and {{fig.sac.keccak.beyond}}, where chance alone would give {{fig.sac.secp256k1.expectedBeyond}}.

On the enumerated curves every bit i of every key is flipped, and each unordered pair \{k, k \oplus 2^i\} with both keys in [1, n - 1] is counted once: {{fig.avalanche.O1051.pairs}} pairs on \mathbb{F}_{1051} and {{fig.avalanche.O16477.pairs}} on \mathbb{F}_{16477}, after {{fig.avalanche.O1051.discarded}} and {{fig.avalanche.O16477.discarded}} flips that left the range were discarded. The output is x and y written in binary, {{fig.avalanche.O1051.outputBits}} and {{fig.avalanche.O16477.outputBits}} bits. Its bits are neither fair (§5.4) nor independent of one another, since y is tied to x by the equation, so the reference is not a binomial law but the exact law of the Hamming distance between two distinct points of the orbit, computed over all {{fig.avalanche.O1051.allPairs}} and {{fig.avalanche.O16477.allPairs}} pairs of points: the distance that a flip would produce if it sent kG to an unrelated point of the orbit. The means agree, {{fig.avalanche.O1051.mean}} against {{fig.avalanche.O1051.expectedMean}} on \mathbb{F}_{1051} and {{fig.avalanche.O16477.mean}} against {{fig.avalanche.O16477.expectedMean}} on \mathbb{F}_{16477}. The shapes agree on \mathbb{F}_{16477} (\chi^2 = {{fig.avalanche.O16477.statistic}} on {{fig.avalanche.O16477.df}} degrees of freedom, yardstick {{fig.avalanche.O16477.pEq}}) and depart mildly on \mathbb{F}_{1051} (\chi^2 = {{fig.avalanche.O1051.statistic}} on {{fig.avalanche.O1051.df}} degrees of freedom, yardstick {{fig.avalanche.O1051.pEq}}), a value of the kind expected now and then among the many statistics of this section. The toy orbit offers only {{fig.avalanche.T17.pairs}} pairs, too few to say anything.

The decisive difference lies elsewhere. Flipping bit i changes the key by \pm 2^i: k' = k + 2^i if the bit was 0 and k - 2^i if it was 1. By the homomorphism, Q' = Q \pm 2^i G, so that, given Q and i, the new public key is one of two points that anyone can compute with one point addition, without knowing k. Table 6 compares each Q' of the sample, computed from scratch, with these two candidates: the prediction holds in {{fig.relatedOutputs.secp256k1.hits}} of {{fig.relatedOutputs.secp256k1.trials}} cases. For Keccak-256 no such relation is known, and the simplest guess, that flipping bit i always changes the digest by the same mask, holds in {{fig.relatedOutputs.keccak.hits}} of {{fig.relatedOutputs.keccak.trials}} cases; applied to the bits of x(Q) it holds in {{fig.relatedOutputs.secp256k1.xorHits}} of {{fig.relatedOutputs.secp256k1.xorTrials}}. The matrix of Figure 11 was in fact computed with the relation, by one point addition per key and input bit rather than by a fresh scalar multiplication. The coordinates avalanche; the points do not. The relation between Q and Q' lives in the group, where no bitwise test looks.

5.8 The cost of inversion

None of the statistics of §5.2 to §5.7 measures the property that defines a one-way function, the cost of inversion. Figure 12 measures it directly on {{fig.ecdlp.curves}} curves y^2 = x^3 + 7 of prime order, from p = {{fig.ecdlp.smallestP}} to p = {{fig.ecdlp.largestP}}, by recovering {{fig.ecdlp.targets}} random keys on each with exhaustive search and with baby-step giant-step. On logarithmic axes the mean costs lie on straight lines with fitted slopes {{fig.ecdlp.bruteSlope}} and {{fig.ecdlp.bsgsSlope}}, close to the theoretical 1 and ½: exhaustive search costs about n/2 group operations, baby-step giant-step about 1.5\sqrt{n} in this implementation. Carried to the order of secp256k1, the fitted lines give about 2{{fig.ecdlp.bruteAt256}} and 2{{fig.ecdlp.bsgsAt256}} operations, against the theoretical 2{{fig.ecdlp.theoryBruteAt256}} and 2{{fig.ecdlp.theoryBsgsAt256}}. This is a long extrapolation, from orders of at most {{fig.ecdlp.largestN}}, below 2^{19}, to about 2^{256}, and the gap for exhaustive search shows how sensitive it is to the fitted slope. Its value lies in its agreement with the theory, which puts the generic cost of the ECDLP on secp256k1 at about 2^{128} group operations [6, §4.1.2], [13, §5.2].

The toy curve fails this test for reasons that no output statistic shows. Its order n = {{fig.ladder.T17.n}} = {{fig.ladder.T17.factors}} is a power of a small prime, so the Pohlig–Hellman method reduces the logarithm to subgroups of order 3 [6, §4.1.1], [13, §5.2.3]. The assignment's key needs even less: Q = 6G has order 9/\gcd(6, 9) = 3, which alone reveals k \equiv 0 \pmod 3 and leaves k \in \{3, 6\}. The curve is also supersingular (§2.3), and n = 9 divides 17^2 - 1 = 288, so the MOV attack transfers the problem to the multiplicative group of the field of 17^2 elements [13, §5.3.1]. The supersingular curve over \mathbb{F}_{1031} shares both weaknesses: its order {{fig.ecdlp.smooth.S1031.n}} = {{fig.ecdlp.smooth.S1031.factors}} has no prime factor larger than {{fig.ecdlp.smooth.S1031.largestPrime}}. Yet the statistics of §5.2 to §5.7 barely set it apart from the curves of prime order: its ordinates are exactly uniform, which follows from p \equiv 2 \pmod 3, and one abscissa occurs once, that of its point of order 2, which betrays the factor 2 of its order and nothing of the rest. The weaknesses that matter are computational and structural, and the statistics of the outputs do not reveal them.

5.9 Summary

Table 7 collects the results. Read by rows, it separates three kinds of property. Some are departures from a random function that the symmetries of the group explain exactly and that do not fade as p grows: the frequencies of values, the mirror images, the related outputs after a bit flip. Some are artefacts of the field size or of smallness that vanish on secp256k1: the bias of the top bits and the correlations of the toy orbit. The rest agree with an ideal function on the larger curves and on secp256k1: the binned coordinates, with a mild departure of the ordinates of \mathbb{F}_{1051} under the structural null of §5.2 ({{fig.coordHist.O1051.yStructuralPEq}}); the cells of the half plane; the balance of the bits; and the avalanche of the output bits, with a mild departure in the shape of the distances on \mathbb{F}_{1051} (§5.7). Only the last row, the cost of inversion, measures what makes a function one-way, and it is the row in which the toy curve and secp256k1 differ most. Table 8 anticipates the discussion of §6.

§6 Discussion: one-way function versus hash function

The question of the assignment needs two definitions. A one-way function is easy to compute and hard to invert: no efficient algorithm, given f(x) for a uniformly random input x, finds a preimage with more than negligible probability [7, §8.1.1], [5, §IV]. Nothing in this definition concerns the appearance of the outputs; it constrains only the cost of inversion, on average over a uniform input. A cryptographic hash function compresses inputs of arbitrary length to a fixed length and must resist three attacks: finding an input with a given digest (preimage resistance), a second input with the same digest as a given one (second-preimage resistance), and any two inputs with the same digest (collision resistance) [11, Defs 1–3], [7, §6.1]. These three are the requirements. Beyond them, the analysis of protocols idealises a hash function as a random oracle, a function whose every output bit is uniform and independent of everything else [1, §1.1, §2], [7, §6.5], and the avalanche of hash bits is judged by the strict avalanche criterion that Webster and Tavares introduced for the components of ciphers [14]. In this random-oracle idealisation a hash is modelled as a random function, so it is expected to pass every statistical test that does not use its definition; nothing of the kind is asked of a one-way function.

With these definitions the properties explored in §5 can be classified, as in Table 8.

Distribution of the coordinates. It is not required of a one-way function. What must be uniform is the input: SEC 1 asks for private keys as close to uniform as possible [3, §3.10.3], and since k \mapsto kG is a bijection from [1, n - 1] onto \langle G \rangle \setminus \{O\}, a uniform key gives a uniform point of the group, whatever its coordinates look like as integers. The exactly uniform ordinates of the supersingular curves and the lumped ordinates of \mathbb{F}_{1051} are equally harmless. For a hash, uniform outputs are part of the random-oracle idealisation: a digest that favoured some values would be distinguishable from a random oracle.

Frequency of individual values. The multiplicities of §5.3 are exact symmetries of the curve, and they are harmless beyond a small constant factor: they tell an attacker that Q and -Q come from k and n - k, and that the three points sharing an ordinate come from keys related by a fixed multiplier, which shortens a search but does not change its order of magnitude. For a hash, the Poisson occupancy that Keccak-256 shows is part of behaving like a random function.

Distribution of bits. The bias of the top bits is inherited from the size of p, is identical for every key and is irrelevant to inversion. A hash whose outputs cover exactly 2^{256} values is expected, under the idealisation, to have unbiased bits, and the frequency test of [12, §2.1] is a standard check of this.

Apparent uniformity. It is cosmetic for a one-way function, whose outputs may display any symmetry that does not lead back to the key. For a hash the expectation is stronger than looking uniform: under the random-oracle idealisation it should pass every test that does not use its definition, and an exact symmetry such as the mirror images of §5.5 would contradict that idealisation.

Correlation between input and output. It is relevant to both as a screen and conclusive for neither. A correlation between k and Q would leak the key, and one between an input and its digest would make a hash distinguishable; but §5.6 exhibits a correlation of exactly zero alongside total dependence.

Avalanche-like behaviour. Avalanche is a design criterion of hash functions. Scalar multiplication satisfies it at the level of bits, yet it carries an exact related-input structure, Q' = Q \pm 2^i G, that would disqualify a hash modelled as a random oracle, since the output for one input becomes predictable from the output for another. For public-key cryptography the same structure is not a defect but the point. It is the homomorphism (a + b)G = aG + bG, which ECDSA verification uses when it computes the combination u_1 G + u_2 Q of public points [3, §4.1.4], and which the non-hardened key derivation examined in Homework 2 uses to compute a child public key from the parent public key alone.

Collisions separate the two notions most sharply. On [1, n - 1] the map k \mapsto kG is injective: distinct keys give distinct public keys, so it has no collisions at all, and collision resistance is not a question for it. A hash compresses an unbounded domain into a finite range, so collisions must exist, and collision resistance means only that none can be found [11, Def. 3]. A function can thus be one-way without resembling a hash, and the two maps that lead to an Ethereum address are asked for different things.

What carries the one-wayness of k \mapsto kG, then, is not a statistic of its outputs. It is, first, the group: a prime order large enough to put \sqrt{n} operations out of reach, and the absence of exploitable structure, such as the smooth order and the supersingularity that make the toy curve and the curve over \mathbb{F}_{1031} easy to invert (§5.8). It is, second, the key. The definition of a one-way function assumes a uniformly random input, and the security of a key pair rests on that assumption being met: Breitner and Heninger computed hundreds of Bitcoin and dozens of Ethereum private keys from signatures whose per-signature secret nonces, themselves scalars fed to k \mapsto kG, were not uniformly random [2]. The defect there lay in the distribution of an input, not in the behaviour of the outputs that §5 examines.

The statistics of the outputs can therefore refute one-wayness but not certify it. A correlation, a visible pattern linking k to Q, or a cost of inversion growing too slowly would be evidence against it; their absence is not evidence for it, as the toy curve shows by passing several of the same tests while being invertible by inspection. For a hash the statistics carry more weight, because the random-oracle idealisation under which a hash is used asks it to behave like a random function, although even there passing them is necessary rather than sufficient. The derivation of an Ethereum address uses each map for what it offers: k \mapsto kG supplies the algebra that signatures need, and Keccak-256 supplies compression and, as far as is known, the behaviour of a random function, turning a structured 64-byte public key into a 20-byte address.

§7 Conclusion

The program of §3 computes the toy public key Q = 6G = {{fig.toy.Q}} from G = {{fig.toy.G}} and k = {{fig.toy.k}}, printing every multiple on the way, and double-and-add reaches the same point in {{fig.toy.dblAddOperations}} group operations instead of {{fig.toy.repeatedOperations}}. On secp256k1 the same method needs about {{fig.dblAddCost.meanDoubleAndAdd256}} operations, where the best generic inversion needs about 2^{128}. The slowed-down view of §4 shows where the asymmetry comes from: the computation advances regularly on the dial of the group and erratically on the sheet of coordinates, and a public key reveals only the second.

To the research question the exploration gives a two-sided answer. A sample of keys reveals a good deal about the outputs of k \mapsto kG: exact symmetries, with abscissas in pairs, ordinates in threes or once and every point mirrored; biases of the top bits set by the size of the field; and an exact related-input structure behind an avalanche that otherwise matches that of Keccak-256. None of these weakens the one-wayness of an Ethereum key, and the only one still visible in a sample of secp256k1 is the last, the homomorphism on which public-key cryptography is built. What one-wayness requires, a large prime order free of exploitable structure and a uniformly random private key, is not a property of the distribution of the outputs, and no statistic of the outputs can certify it. Output statistics that mimic a random function are the business of hash functions; one-wayness belongs to the hardness of the discrete logarithm and to the randomness of the key.
